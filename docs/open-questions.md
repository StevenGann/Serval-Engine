- [x] Later engine properties and instance fields share Lua's field names ([lua.md](lua.md#what-compiles-to-what)): any field name that isn't a property is an instance field, so a property added later would take a name scripts may already use for a field of their own, and change what those scripts mean (the properties added before rc.1, `body_bounce` to `object`, took their names while no release had them). Decided 2026-10-08, before 1.0.0: instance fields can't start with `anim_`, `body_`, `ent_`, `map_`, `path_`, `pos_`, `spr_`, `vel_` or `vm_` (a compile error, whose hint suggests a new name, or the property a field looks like), and every property added later has a name with one of those prefixes, so adding one breaks no script; no short names are reserved ([lua.md](lua.md#reserved-names), [api-freeze.md](api-freeze.md#decisions), D8).
- [x] Builtins and a script's own names: a script can't declare a builtin's name at the top level, and builtins are named after the C functions they call, so a planned function's builtin, arriving with its implementation, would stop a script that declared its name compiling. Decided 2026-10-09, before 1.0.0: every function the headers mark `SERVAL_PLANNED` is reserved where a builtin's name is refused (top-level declarations), read from the markers by `svlua.py`, and using one says it is planned; locals and parameters may take the names ([lua.md](lua.md#planned-functions), [api-freeze.md](api-freeze.md#decisions), D9).
- [ ] Builtins for engine functions that 1.0 doesn't declare: a function added in a 1.x minor (`button_released()`, say; [api-freeze.md](api-freeze.md#later-additively-no-api-now)) whose builtin takes its C name, as builtins do, would stop compiling a script that declared that name, which nothing reserves. Before 1.0.0, decide between declaring such functions planned first (the reservation then covers them), letting a script's own top-level name win over builtins added after 1.0 (with a warning), or giving them no builtins.
- [x] The freeze's other decisions ([api-freeze.md](api-freeze.md#decisions)): hazards are tags (above); writing `ent_mask` directly stays legal forever (`ent_add()`/`ent_remove()` helpers may come as wrappers); palette writes are copy-on-write, so palette sharing can come later unseen; alpha blending pauses while `screen_set_brightness()` is not 0 (the hardware has one color effect, and the fade wins); volumes are 0-15 for the PSG (the hardware's steps) and 0-255 for the mixer; streaming is per sprite group only (`SpriteGroup.flags`; bit 0 of `SpriteAsset.flags`, once `SPRITE_ASSET_STREAMED`, is reserved).

## API caveats found by the examples

Not bugs, but surprises a game developer hit while writing the examples (details in [api-reference.md](api-reference.md)); each could be smoothed by an API change. Decide for each whether to change the API or keep the caveat. The caveats that remain at 1.0.0-rc.1 are listed in [api-freeze.md](api-freeze.md#caveats-that-remain).

- [x] `PathStep` needs designated initializers: a positional initializer that leaves fields out trips `-Wmissing-field-initializers` ([runtime-systems.md](runtime-systems.md#paths)). Kept: a C rule; the docs use designated initializers everywhere.
- [x] `camera_set()` clamps silently: with a playfield smaller than the screen it stays at 0, so moving a small layer with the camera does nothing (Blackjack's swirl; use `map_set_scroll()`) ([runtime-systems.md](runtime-systems.md#camera)). Changed: clamping at the edges stays silent, but asking for a non-zero position on an axis where the playfield is smaller than the screen warns once, naming `map_set_scroll()`.
- [x] `body_max_fall` was whole pixels per frame (`u8`), so a top speed of 1.5 was not possible (Breakout's capsules went from 1.5 to 2). Changed: a `u16` in fixed point (`FX(3) / 2`); the capsules fall at 1.5 again.
- [x] `SPRITE_SCREEN` bodies and world bodies: `body_overlap()` compared positions as they are, so testing a screen-space entity against a world-space one needed the camera added by hand. Changed: `body_overlap()` and `body_hit_side()` add the camera for such pairs (Shmup's shots against turrets).
- [x] `BODY_CONTACT_EXIT` counts a body touching an open edge from outside as gone, one frame earlier than a game's own `pos < -w` test; use one test or the other, not both. Kept: the engine is right (at `pos == -w` the body's last column is already outside, so `pos < -w` is the test that is a frame late); the docs give the exact test per edge and say to use `BODY_CONTACT_EXIT`.
- [x] `button_repeat()` repeats a button that is still held when a screen opens (say, from gameplay into initials entry); games check `button_pressed()` first when a screen should wait for a fresh press. Changed: `button_repeat_reset()`, called when a screen opens, silences every button held then until it is released (the delay and interval, `button_pressed()` and `button_down()` are unaffected).
